# Swarmwatch

A Google-authenticated workspace for supervising 1–3 named agents. Each agent has a goal, shared Inkbox iMessage calling, a conversation history, and an observed-behavior sentiment score. A shared company mission guides every agent.

This repository is the Java 25 / Spring Boot service. The React dashboard is in [sdev138/nanda-frontend](https://github.com/sdev138/nanda-frontend), and the unchanged protocol reference is in [sdev138/personal-agent-protocol](https://github.com/sdev138/personal-agent-protocol). Clone these repositories beside each other to follow the commands below.

## Run locally

Requirements: Java 25, Node.js 22.18+ (Node 26 used for verification), and npm. The Gradle wrapper is included.

In one terminal:

```sh
cd Swarmwatch-svc
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
./gradlew bootRun --args='--spring.profiles.active=local --server.address=127.0.0.1'
```

In another terminal:

```sh
cd nanda-frontend
npm ci
npm run dev
```

Open [the dashboard](http://localhost:5173). Choose **Open local workspace**, enter a company mission, then create agents. Local mode uses in-memory persistence, simulated phone lines, simulated provider responses, and a fixed local authentication identity. It never accesses cloud secrets, registers live identities, or places calls. Data resets when the service stops. Stop both terminal processes with Ctrl+C when finished.

The frontend proxies `/api` to `127.0.0.1:8080`. Set `VITE_API_URL` only when using a different API origin with appropriate hosting configuration. Production hosting should serve the frontend and `/api` through one origin.

## Connect the real providers

Production is the default profile. It does not fall back to local authentication or simulated providers.

Set `GCP_PROJECT_ID` at runtime and use Application Default Credentials. Run `gcloud auth application-default login` if the machine does not already have ADC. The project needs a **Datastore-mode** default database. The Cloud Run deployment provisions the required Datastore-mode database and supplies the project ID at runtime.

The backend retrieves `openai-secret` and `inkbox-secret` from Google Secret Manager. Never put these keys in frontend environment variables or source files. Nanda registration creates per-agent password secrets named `sw-nanda-<hash>`; the runtime identity needs Secret Manager secret creation, version addition/access, and deletion for those secrets, plus access to the two provider secrets and Datastore read/write permissions.

Set `GOOGLE_CLIENT_ID` to your Google OAuth web client ID at runtime. Account-specific configuration is excluded from Git. For local live settings, create an ignored `config/application-live.properties` containing these two settings and use `--spring.profiles.active=live`; no account-specific file is included in this repository.

Allow `http://localhost:5173` as an authorized JavaScript origin in the OAuth client. Add `http://127.0.0.1:5173` if using that address. Add the final production HTTPS origin when deployed. Google Identity Services returns an ID token; the backend verifies its audience, issuer, signature, expiry, and verified email. This flow does not require `OAuth-Client-Secret`, which remains in Secret Manager.

Start without `--spring.profiles.active=local` to use real integrations. No agents are created at startup. Returning users recover their existing tenant and agents. A first signup proposes a UUID generated by the frontend; the backend binds it once to the verified Google subject.

Core environment settings:

- `GCP_PROJECT_ID`: your GCP project ID; required for real providers.
- `GOOGLE_CLIENT_ID`: your Google OAuth web client ID; required for real sign-in.
- `CHECK_INTERVAL_SECONDS`: defaults to 60.
- `OPENAI_BASE_URL`: defaults to `https://api.openai.com/v1`.
- `INKBOX_BASE_URL`: defaults to `https://inkbox.ai/api/v1`.

## Agent behavior

The company mission is required before agent creation. Every agent receives it in its system instructions, along with its individual goal. Editing the mission updates subsequent agent turns and standing phone instructions. Inbox content, phone transcripts, and peer messages are treated as external context.

The runtime processes turns sequentially with RxJava. Pending owner messages take precedence; otherwise the exact check-in prompt is **How are you doing and what are you working on?** A failed provider operation keeps queued work and the last valid sentiment visible for investigation.

GPT-6-Luna runs with high reasoning. The separate Decisions endpoint, `/v1/decisions`, also uses `gpt-6-luna`; there is no separate Decisions model ID. It assesses observable adherence to the mission and goal. Scores are estimates, not proof of internal intent, and no private chain-of-thought is requested or displayed.

- `0.00–0.25`: red, investigate.
- `0.26–0.50`: yellow, needs review.
- `0.51–1.00`: green, on task.

New agents start at exactly `0.51`, labeled as awaiting their first assessment. The UI polls every four seconds, shows phone transcripts and peer conversations, and supports user direction, immediate check-ins, outbound call requests, agent collaboration, and deletion.

New agents enable shared iMessage calling without claiming a dedicated phone number. In the inspector, text the current connection command to Inkbox's router, then call the contact Inkbox sends back. Each recipient must connect before the agent can call them. The router is retrieved at runtime and is not the agent's public number. Free accounts include a one-time organization-wide pool of 30 US/Canada call minutes; check Inkbox for current plan limits. Existing agents with dedicated numbers retain their calling path.

Inkbox hosted voice answers calls for the identity. Its voice model is selected by Inkbox; it is not advertised as GPT-6-Luna. Recorded transcripts return to the service's conversation history and assessment context. Deleting an agent removes its Inkbox identity and persisted state, releasing any legacy dedicated number, with visible errors and retry paths when provider cleanup fails.

## Model tools

Every agent uses Responses tools for web search, hosted shell, file search, computer use, and tool search. Phone calls and agent collaboration are available as deferred functions. Hosted tools run only in real-provider mode; local mode simulates them.

Each agent has a separate file-search vector store seeded with its shared mission and individual goal. Resource IDs are checkpointed for retryable creation, refresh, and deletion. Full conversation history remains in Datastore; provider prompts use bounded recent context. Agent entities retain a bounded recent `agent_responses` projection while the conversation endpoint preserves the full history.

Computer use has an isolated Chromium browser context per tenant/agent. It does not use your own browser profile, desktop, credentials, or host shell. Install its matching browser before enabling live use:

```sh
cd Swarmwatch-svc
./gradlew playwrightInstall
```

If using `PLAYWRIGHT_BROWSERS_PATH`, set the same path for installation and service runtime. Linux needs the corresponding Playwright browser system libraries. Keep the Chromium sandbox enabled and deploy under a dedicated non-root user/container. Public-address validation and a pinning proxy reject private/loopback destinations and redirects. Missing browser binaries produce a visible error.

The actual-browser smoke is opt-in, runs on a local static page, and visits no external site:

```sh
NANDA_COMPUTER_SMOKE=true ./gradlew test
```

## Discovery and protocol scope

Nanda registration follows account verification, entry creation, entry verification, and public resolution. Polling is durable and no faster than once every 30 seconds. Shared-call connection instructions are the primary UI contact; legacy dedicated agents show their number. Nanda currently requires a verified **email-derived** personal locator, so the Inkbox mailbox is used internally for registration; the API does not support phone-only personal registration. Registration status appears in the inspector.

Same-workspace agent collaboration records Personal Agent Protocol 1.0 message envelopes with an identified author. This is an internal adapter. It does not claim public PAP federation, verified external Poppy Sessions, a public OAuth server, or a telephony standard defined by PAP. Nanda's A2A card and PAP are distinct protocols. Registry deletion removes the public listing and the service-owned registration password; the external Nanda account is retained.

## Verify

```sh
cd Swarmwatch-svc
./gradlew test bootJar
```

```sh
cd nanda-frontend
npm test
npm run build
npm run lint
```

Tests use local provider HTTP fixtures; they do not call live numbers or create cloud resources. Browser verification uses the local application. The service is designed for one running instance: per-tenant creation locks and a single turn queue do not provide distributed worker leases across replicas.

The JSON API contract is in [docs/api-contract.md](docs/api-contract.md). The API contract is included with this repository.
